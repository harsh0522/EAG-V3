Session 6 splits a single LLM call into four cognitive roles — Memory, Perception, Decision, Action — connected by Pydantic contracts. These four queries prove the architecture works end to end.

Memory storage
state/memory.json — keyword overlap search. No vectors yet (that's Session 7).
Artifact store
state/artifacts/ — raw bytes for large payloads (web pages, docs). Separate from memory.
LLM Gateway
Gateway V3 at localhost:8100. Every LLM call goes through here. Router pool with failover.
Invariant
Perception never names specific tools. Decision is atomic — one action per step.
4 Target Queries

A through D — must all pass

A
QUERY A 3 iter expected · 6 hard cap Passed
Shannon Wikipedia
Fetch https://en.wikipedia.org/wiki/Claude_Shannon and tell me his birth date, death date, and three key contributions to information theory.
You give the agent a link and ask it to find specific facts. It fetches the Wikipedia page — a large document — stores it as an artifact (a separate store for raw content, not memory), then Perception attaches that artifact to the extraction goal so Decision can read it and answer in one step.
What this tests
The full artifact pipeline: fetch → store as artifact → Perception attaches it to the next goal → Decision extracts structured facts. The key rule: Decision must act in one step. Perception cannot tell Decision to "first read the artifact, then answer" — that is two steps and breaks the architecture.
B
QUERY B 6 iter expected · 12 hard cap Passed
Tokyo Activities + Weather
Find 3 family-friendly things to do in Tokyo this weekend. Check Saturday's weather forecast there and tell me which one is most appropriate.
One question with three logical steps: find activities, check the weather, recommend based on the weather. Perception decomposes it into three separate goals. The weather result from goal 2 is saved to memory as a tool outcome. When goal 3 runs, Memory surfaces that outcome through keyword matching so Decision can use it.
What this tests
Multi-goal planning and memory carryover between goals. The agent must plan ahead, not just react. And the memory keyword search must surface the right tool outcome when goal 3 asks for it — this is where S6's simple keyword memory is genuinely tested.
C
QUERY C 4 + 2 iter expected · 8 + 4 hard cap Key Demo
Mom's Birthday — Two Runs
RUN 1 · 4 iterations
My mom's birthday is 15 May 2026. Remember that and create reminders for two weeks before and on the day.
You tell the agent a personal fact. It classifies this as a preference (not a scratchpad), saves it to state/memory.json on disk, and creates two reminder files in the sandbox. The fact survives because it's written to disk — not just held in the current process.
RUN 2 · 2 iterations · Fresh process · Zero tool calls
When is mom's birthday?
The app is completely closed and restarted. Fresh process, empty RAM. The agent reads memory.json from disk on its first iteration, keyword-matches "birthday" to the stored fact, and answers directly. No tool calls at all — the answer comes entirely from persisted memory.
What this tests
Durable memory across process restarts. The state/ directory is what crosses the process boundary. This is why memory is written to disk synchronously on every write — so that a cold-start on the next run sees exactly what was saved. In S6 this uses keyword search; in S7 the same pattern uses FAISS vectors instead.
D
QUERY D 5–7 iter expected · 14 hard cap Passed
Asyncio Research — Multi-Source Synthesis
Search for "Python asyncio best practices", read the top 3 results, and give me a short numbered list of the advice they agree on.
Search the web, fetch three different articles as artifacts, then synthesize what all three agree on. The hardest part is the synthesis step — Perception must attach all three artifacts to the synthesis goal so Decision can read all three at once and find common advice across them.
What this tests
Multi-source synthesis and the force-attach pattern. Three separate artifacts must all be attached to a single synthesis goal. The agent loop auto-attaches artifacts that Perception flags — but Perception must correctly identify all three as relevant. If only two get attached, the synthesis is incomplete. This query also has the highest iteration variance across runs (5 to 7) because web search results differ each time.
