Your Questions — Direct Answers

Can the agent use Gemini?
YES — Required
Perception is pinned to Gemini (provider="g"). Memory.remember is also pinned to Gemini. Without GEMINI_API_KEY the agent cannot run.
Can Decision use GROQ?
YES — Auto-routed
Decision sends auto_route="decision" to the Gateway. The Gateway picks the best provider from its pool — GROQ is in that pool. So yes, Decision can use GROQ (and Cerebras, NVIDIA, etc.).
Does Action require an LLM?
NO — Zero LLM calls
Action is pure MCP dispatch. It calls a tool over stdio, collapses the result, and optionally saves it as an artifact. No AI involved.

This is a four-role agentic loop. Instead of one big LLM call that "thinks and acts," the work is split into four specialist roles that each do one thing:

Everything flows through the LLM Gateway V3 at http://localhost:8101. The gateway handles provider selection, fallbacks, caching, and reasoning routing. Your code never calls Gemini or GROQ directly.

The Main Loop — How a Query Runs

for each query:
  1. memory.remember(query)        ← classify and save any durable facts BEFORE the loop
  2. open MCP server as subprocess
  3. for iter = 1 to 14:
       a. hits = memory.read(query, history)     ← keyword search, no LLM
       b. obs  = perception.observe(...)          ← Gemini decomposes/updates goals
       c. if ALL goals done → break
       d. goal = first unfinished goal
       e. if goal.attach_artifact_id → load bytes from ArtifactStore
       f. out  = decision.next_step(goal, hits, attached_bytes, ...)   ← auto-routed LLM
       g. if out.answer → record in history, continue
       h. (result_text, art_id) = action.execute(out.tool_call)        ← MCP call, no LLM
       i. memory.record_outcome(...)              ← save tool result to memory
       j. record in history
  4. extract final answer from history
Key insight about termination: The loop breaks when Perception marks all goals done. Decision never says "I'm done." Only Perception, by examining history on each iteration, can declare a goal satisfied. This is why Perception runs every single iteration even when there's nothing new to do.

📁 prompts/ — What This Folder Does

The prompts/ folder contains the system prompts for the two roles that use LLMs: Perception and Decision.

prompts/perception_system.md

Who reads it: perception.py loads it via Path(...).read_text() and sends it as the system field to the Gateway.

What it tells Gemini:

  • Obligation 1: If no prior goals exist, decompose the query into bounded goals.
  • Obligation 2: Mark a goal done when history proves it's satisfied. Never un-done a goal.
  • Obligation 3: For the first unfinished goal, pick which artifact to attach (by index).
  • Obligation 4: Never reorder, never drop goals — just update done flags.

Output schema: The prompt specifies exactly {"goals": [{"text", "done", "attach_artifact_index"}]}. No id field — ids are assigned by the loop by position (g1, g2, …).

Why a file, not inline? It's much easier to tune prompts when they're in plain text files. Change the file, re-run — no code change needed.

prompts/decision_system.md

Who reads it: decision.py sends it as the system prompt to the Gateway with auto_route="decision".

What it tells the LLM (GROQ or whichever provider is chosen):

  • Rule 1: Respond with exactly ONE thing — either an answer OR a tool call. Never both.
  • Rule 2: art: strings are NOT file paths. Never pass them to a tool's path or url argument.
  • Rule 3: Answers must be substantive. No "the page has been fetched" meta-answers.

Why these rules? These are the most common failure modes in agentic systems. Rule 1 prevents ambiguous output. Rule 2 prevents artifact handle leaks. Rule 3 prevents the agent from looping forever without making progress.

Why Query C (Mom's birthday) works across restarts: When you type "My mom's birthday is 15 May 2026", the loop calls memory.remember(query) BEFORE the first iteration. 📁 logs/ — Run History (gitignored)

One JSONL file per run: logs/run-<run_id>.jsonl. Every event emitted by logger.py is appended here as one JSON line.

The dashboard's Replay dropdown loads these files via GET /api/runs/{run_id} and re-streams the events through the same rendering code — so you can re-watch any past run without re-running the agent.

📄 schemas.py — Pydantic Contracts

The "language" that the four roles speak to each other. Every boundary between roles is a typed Pydantic model. No raw dicts passed between roles.

schemas.py 6 models All Pydantic v2 data contracts
class MemoryItem(BaseModel):
What gets stored in state/memory.json. Has kind (fact/preference/tool_outcome/scratchpad), keywords for search, descriptor (human-readable), value (structured data), and optionally artifact_id pointing to a stored file.
class Artifact(BaseModel):
Metadata for a stored file. The id looks like art:09ff0a67fe264eb9. The actual bytes live in state/artifacts/09ff0a67fe264eb9.bin.
class Goal(BaseModel): id: str # "g1", "g2", ... text: str done: bool attach_artifact_id: str | None
One task for the agent. The id is assigned by position in the loop (not by the LLM). done is set by Perception. attach_artifact_id tells the loop which artifact to load and pass to Decision.
class Observation(BaseModel): goals: list[Goal]
Output of Perception. Just a list of goals. The loop iterates over these to find the first undone one.
class DecisionOutput(BaseModel): answer: str | None = None tool_call: ToolCall | None = None @model_validator(mode="after") def exactly_one(self):
Output of Decision — enforces the one-or-the-other contract. The model_validator runs after construction and raises a ValueError if both or neither are set. This is caught by log_construct() and logged as a pydantic error.

📄 logger.py — Structured Event Logger

The single source of truth for all observability. Every role calls logger.py functions. Never print() directly from roles.

logger.py 3 sinks stdout + JSONL file + SSE queue
_SSE_QUEUE: asyncio.Queue | None
The bridge to the browser. agent6.py calls log.set_sse_queue(q) at startup, wiring the dashboard's queue into the logger.
def _emit(event: dict): # 1. stdout — human readable # 2. JSONL file # 3. SSE queue (put_nowait)

📄 memory.py — Memory Service + ArtifactStore

Two classes in one file: Memory (reads/writes state/memory.json) and ArtifactStore (reads/writes state/artifacts/).

memory.py — Memory class Gemini for remember() No LLM for read()

Memory.read() — Pure Python keyword search

q_tokens = _tokenize(query) for h in history[-5:]: q_tokens |= _tokenize(h.get("result_descriptor",""))
Build a token set from the query PLUS recent history. This means if you just fetched a page about "Shannon", those tokens get added, improving recall for follow-up goals.
overlap = len(q_tokens & item_tokens) if overlap > 0: scored.append((overlap, item))
Simple overlap scoring. Count shared lowercase tokens. No TF-IDF, no embeddings, no semantic similarity. Intentionally "dumb" so you can see exactly what memory retrieves and why.

Memory.remember() — Gemini classifies the query

resp = await _gateway_call( messages=[...], provider="g", # ← Gemini response_format={"type": "json_object"}, )
Calls Gemini with a prompt asking: "Is there any durable fact/preference in this text? Return JSON {kind, keywords, descriptor, value} or {} if nothing durable." The keywords list is what makes future searches work.
if not parsed or not parsed.get("kind"): return None
Returns None if the query has no durable content. For example "What is 2+2?" — no fact to remember. The loop handles None gracefully (logs "no durable content" and continues).

Memory.record_outcome() — No LLM

keywords = list({tool_call.name} | args_tokens)[:8] descriptor = f"{tool_call.name}({_args_repr(...)}) -> {artifact_id}" item = MemoryItem(kind="tool_outcome", ...)
Called after EVERY action. Saves what tool was called and what it produced (or what artifact it created). These records are what Perception sees in MEMORY HITS on the next iteration — enabling it to say "fetch_url already ran, mark that goal done."
memory.py — ArtifactStore class No LLM
sha = hashlib.sha256(blob).hexdigest()[:16] art_id = f"art:{sha}" bin_path = _ARTIFACTS_DIR / f"{sha}.bin"
Content-addressable storage. The same bytes always produce the same handle. If you fetch the same URL twice, the second call is a no-op (idempotent). The 16-char SHA prefix is enough to avoid collisions for hundreds of artifacts.
def _atomic_write(path: Path, data: Any): tmp = path.with_suffix(".tmp") tmp.write_text(...) tmp.replace(path) # atomic rename
Atomic writes prevent corruption. If the process crashes mid-write, you get the old file rather than a half-written one. rename() is atomic on POSIX systems.

📄 mcp_server.py — The 9-Tool MCP Server

A standalone Python process that the agent spawns as a subprocess and communicates with over stdio. The agent never calls these functions directly — it sends JSON requests over the MCP protocol, and the server responds.

ToolWhat it doesNotes

SANDBOX = Path(__file__).parent / "sandbox" def _sandbox(path: str) -> Path: resolved = (SANDBOX / path.lstrip("/")).resolve() if not str(resolved).startswith(str(SANDBOX.resolve())): raise ValueError(f"Path {path!r} escapes sandbox")
Security: sandbox all file operations. If the LLM tries to write to ../../.env or /etc/passwd, this catches it. .resolve() expands symlinks and .. before checking the prefix.
try: loop = _aio.get_event_loop() if loop.is_running(): with ThreadPoolExecutor() as pool: future = pool.submit(_aio.run, _crawl()) return future.result(timeout=120)
Async event loop conflict fix. crawl4ai is async, but the MCP server runs in the agent's already-running event loop. You can't call asyncio.run() inside a running loop. Solution: run it in a separate thread where the event loop is not yet running.

📄 action.py — Pure Dispatch (No LLM)

NO LLM CALLS

The simplest role. Takes one ToolCall, calls the MCP server, handles the result. About 50 lines of real logic.

action.py No LLM MCP dispatch + artifact threshold
_PATH_KEYS = re.compile(r"^(path|url|file|location)$") for key, val in tool_call.arguments.items(): if _PATH_KEYS.match(key) and val.startswith("art:"): log.action_guarded(...) return ("error: artifact handles are not paths/urls...", None)
Artifact-handle guard. If Decision (despite being told not to) passes an art: string as a url argument, this catches it before the MCP call. Logged as "guarded" — visible as a red warning in the dashboard's Action column.
result = await session.call_tool(tool_call.name, arguments=tool_call.arguments)
The actual MCP call. Sends a JSON-RPC request over stdio to the running mcp_server.py process and awaits the response.
ARTIFACT_THRESHOLD_BYTES = 4096 if len(text.encode("utf-8")) > ARTIFACT_THRESHOLD_BYTES: art_id = self.artifacts.put(text.encode("utf-8"), ...) return (f"[artifact {art_id}, {n} bytes] preview: {text[:300]}", art_id)
Large results become artifacts. Anything over 4 KB is saved to disk and referenced by handle. This keeps the history and prompt sizes small — Decision only sees the full bytes when Perception explicitly attaches them.

📄 perception.py — The Orchestrator Role

PINNED TO GEMINI

Perception runs every single iteration. It decides what's been accomplished and what needs to happen next.

perception.py provider="g" (Gemini) Goal decomposition + progress tracking
hits_lines = [] for i, h in enumerate(hits): line = f"[{i}] kind={h.kind} descriptor={h.descriptor!r}" if h.artifact_id: line += f" artifact_index={i}"
Build the MEMORY HITS section. Only hits WITH an artifact get an artifact_index=N label. That number is what the model emits back as attach_artifact_index. The loop then maps the integer back to the real art: handle.
response_format={ "type": "json_schema", "schema": _OUTPUT_SCHEMA, "name": "Observation", "strict": True, }
Structured output. The gateway forces Gemini to return valid JSON matching the schema. No regex parsing needed. The schema has NO id field — ids are assigned by the loop afterward.
_SYNTHESIS_KEYWORDS = {"synthesise","synthesize", "extract","list","compare","decide"} if words & _SYNTHESIS_KEYWORDS: artifact_hits = [h for h in hits if h.artifact_id] if artifact_hits and first_open.attach_artifact_id is None: first_open.attach_artifact_id = artifact_hits[-1].artifact_id
Force-attach safety net. For Query D (asyncio synthesis), the model might forget to set attach_artifact_index. This code runs AFTER parsing and overrides: if the goal contains synthesis keywords AND there are artifact hits AND the model didn't attach one — force-attach the most recent artifact. This is what makes Query D reliably work.

📄 decision.py — One Goal, One Answer

AUTO-ROUTED (GROQ, Cerebras, etc.)

Decision receives one goal and has exactly two possible outputs: call a tool, or produce an answer. The DecisionOutput Pydantic model enforces this — exactly one field must be set.

decision.py auto_route="decision" Tool call or answer, never both
art_section = "" if attached: for art_id, blob in attached: text = blob.decode("utf-8", errors="replace") if len(text) > 32 * 1024: text = text[:32768] + "\n[...truncated...]" art_section += f"--- {art_id} ({len(blob)} bytes) ---\n{text}\n--- end ---"
Inject artifact bytes into the prompt. When Perception sets attach_artifact_id, the loop loads the .bin file and passes bytes here. Decision sees up to 32 KB of raw text in its prompt. This is how it can answer "what is Shannon's birth date?" without re-fetching the page.
resp = await _gateway_call( ..., auto_route="decision", tools=mcp_tools, tool_choice="auto", )
auto_route="decision" + tools. The gateway routes to its decision-tier pool (GROQ, Cerebras, etc.). The tool list is passed so the LLM can call any of the 9 MCP tools. tool_choice="auto" means it can also choose NOT to call a tool and just answer.
tool_calls = resp.get("tool_calls", []) if tool_calls: out = log.log_construct(DecisionOutput, tool_call=ToolCall(name=..., arguments=...)) else: out = log.log_construct(DecisionOutput, answer=resp.get("text"))
Parse into DecisionOutput via log_construct. If the response has tool_calls, wrap the first one. Otherwise treat the text response as an answer. log_construct validates through Pydantic AND emits a pydantic event to the dashboard.

📄 agent6.py — The Orchestrator

The main entry point. Starts the dashboard, opens the MCP server, and runs the query loop.

agent6.py Entry point Loop + REPL + gateway lifecycle
from dotenv import load_dotenv from pathlib import Path load_dotenv(Path(__file__).parent / ".env") # MUST be first — before any other import
Load .env FIRST. The gateway and provider SDKs read environment variables at import time. If you load the .env after importing them, the keys won't be seen. This is why these two lines are at the very top before any other imports.
def ensure_gateway(): try: r = httpx.get(f"{GATEWAY_URL}/v1/providers", timeout=3) if r.status_code == 200: return # already running except: pass # Start it as a subprocess _gateway_proc = subprocess.Popen([python, "main.py"], ...)
Auto-start the gateway if needed. If you start agent6.py before starting the gateway manually, it automatically launches it. Polls for 30 seconds before giving up.
async with mcp_session() as session: # StdioServerParameters: command=python, args=["mcp_server.py"] # mcp_server.py runs as a SUBPROCESS
MCP over stdio. The agent spawns mcp_server.py as a child process. They communicate by writing JSON to each other's stdin/stdout. The ClientSession handles all the protocol details. When the context manager exits, the subprocess is killed cleanly.
classified = await memory.remember(query, source="user_query", run_id=run_id) log.memory_remember(classified) # ← This happens BEFORE iter 1
Durable-memory contract. The user's query is classified for facts BEFORE the loop starts. This is what makes Query C work — "My mom's birthday is 15 May 2026" gets saved as a fact with keywords ["mom","birthday","may","2026"] even before the loop tries to do anything with it.
