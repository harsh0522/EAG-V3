AI Prompt Builder & Evaluator

You type a rough project idea. The app runs it through 4 chained LLM agents, builds a high-quality prompt, scores it on 8 criteria, improves it, and returns a final evaluated result — all as structured JSON.

#1 What does this project do?

The Core Idea

Most people give AI a vague, poorly-structured prompt. This tool takes your rough idea and automatically transforms it into a production-quality LLM prompt using a pipeline of 4 specialised AI agents — a Builder, an Evaluator, an Improver, and a Re-Evaluator. Each agent's output is the next agent's input. The final result is a fully validated, scored JSON document.

#2 File Structure
main.py

Entry point. Reads your idea from the terminal, loads the .env file, calls the evaluator, and prints the final JSON.

gateway_client.py

The only place that talks to the LLM. Sends HTTP POST requests to the local LLM Gateway at localhost:8100. No SDK, no LangChain.

models.py

Pydantic data models. Every piece of data entering or leaving the pipeline is validated here — wrong types fail fast.

prompts.py

All system prompt strings live here. Separating prompts from logic makes them easy to tune without touching business logic.

evaluator.py

The brain. Orchestrates the 4-step LLM pipeline, handles JSON parse failures with one retry, and assembles the final output.

.env

Holds your API key, model name (gemini-preview-lite-3), provider, and gateway URL. Loaded at startup.

pyproject.toml

Package config for uv. Declares two dependencies: pydantic and httpx.

tests/sample_inputs.json

Two ready-made project ideas you can paste in to test the pipeline without having to think of something.

#3 The 4 LLM Steps (inside evaluator.py)
Every step follows the same pattern: call call_llm(system_prompt, user_message) → get back a string → parse it as JSON → validate with Pydantic → pass result to next step. If JSON parsing fails, it retries once with "Return only valid JSON, no extra text."
1
Prompt Builder Agent

Turn the rough idea into a proper LLM prompt

Takes your raw idea and thinks step-by-step about what a good LLM prompt for it would look like. It figures out the right tone, structure, features to include, and reasoning approach.

IN: your raw idea (string) OUT: generated_prompt, reasoning, reasoning_type, included_features, confidence
2
Prompt Evaluator Agent

Score the generated prompt on 8 quality criteria

A strict evaluator that reads the generated prompt and checks each of 8 dimensions: Does it ask for explicit reasoning? Structured output? Does it handle failures? Does it use correct framing? Each is a true/false score.

IN: generated_prompt from Step 1 OUT: 8 boolean scores + overall_clarity string → validated as PromptReview
3
Prompt Improver Agent

Fix every criterion that scored false

Receives both the original prompt AND the first review. It reads which criteria failed, explains why (weaknesses_found), and rewrites the prompt so all 8 pass. Thinks step-by-step before writing the improved version.

IN: generated_prompt + first_review JSON OUT: weaknesses_found, improved_prompt, reasoning, confidence
4
Prompt Re-Evaluator Agent

Re-score the improved prompt (same agent as Step 2)

Runs the exact same evaluation as Step 2, but now on the improved prompt. This gives a fair "before vs after" comparison. The self_check field is then computed: if all 8 booleans are now true → "All 8 criteria passed." Otherwise it lists which ones still failed.

IN: improved_prompt from Step 3 OUT: 8 boolean scores + overall_clarity → validated as PromptReview
#4 The 8 Evaluation Criteria
explicit_reasoning

Does the prompt ask the model to think step by step or show its reasoning before answering?

structured_output

Does it ask for output in a specific format — JSON, markdown table, numbered list?

tool_separation

Are different capabilities (search, compute, retrieval) clearly separated as distinct tools?

conversation_loop

Does it allow for back-and-forth — asking clarifying questions or iterating?

instructional_framing

Is the LLM given a clear role or persona to frame how it should respond?

internal_self_checks

Does the prompt ask the model to review or verify its own output before returning it?

reasoning_type_awareness

Does the prompt specify which type of reasoning to use (deductive, analogical, causal)?

fallbacks

Does the prompt tell the model what to do when it's uncertain or can't complete the task?

#5 Pydantic Models (models.py)
Why Pydantic? Every JSON response from the LLM is parsed and validated through a Pydantic model. If the LLM returns a wrong type (e.g. a string where a bool is expected), Pydantic raises an error immediately. This prevents silent bugs from propagating through the pipeline.

#6 How the LLM Gateway Works

Why a Gateway instead of calling the API directly?

The LLM Gateway runs locally at http://localhost:8100. It acts as a universal router — you tell it which provider and model to use, and it handles authentication, rate-limiting, and model-specific formatting. The app itself never holds or uses raw API keys in its code — they stay in .env and on the gateway server. 

# gateway_client.py — the only file that makes HTTP calls

class LLM:
    def chat(self, prompt, *, system, provider, model, ...):
        body = { "prompt": ..., "system": ..., "provider": "google",
                 "model": "gemini-preview-lite-3", ... }
        r = httpx.post("http://localhost:8100/v1/chat", json=body)
        return r.json()   # → { "text": "..." }

def call_llm(system_prompt, user_message):
    result = LLM().chat(...)
    return result["text"]   # ← evaluator.py only sees the raw text string
#7 Environment Variables (.env)
LLM_GATEWAY_V2_URL=http://localhost:8100   # where the gateway runs
GEMINI_API_KEY=your_gemini_api_key_here    # ← replace this with your real key
LLM_MODEL=gemini-preview-lite-3            # which model to use
LLM_PROVIDER=google                        # which provider
Important: Replace your_gemini_api_key_here with your actual Gemini API key. The key is loaded at runtime by main.py — it is never hardcoded into the Python files.
#8 How to Run It

Make sure your local LLM Gateway is running at http://localhost:8100.

Edit .env and replace your_gemini_api_key_here with your real Gemini API key.

Install dependencies with uv: uv pip install pydantic httpx

Run the app: python main.py

Type your rough project idea when prompted and press Enter. Wait ~30–60 seconds while the 4 agents work.

Read the final JSON output in your terminal — it contains the original idea, improved prompt, two scorecards, weaknesses, and confidence score.
