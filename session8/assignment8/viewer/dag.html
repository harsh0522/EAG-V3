Session 8 removes that barrier. Instead of a loop, the agent uses a Directed Acyclic Graph. The Planner writes the whole plan as a graph. The Executor runs every node whose dependencies are done — in parallel if they share none.

Core concept
What a DAG is
Directed Acyclic Graph — the biggest mental shift from S7 to S8.
🎙Explain D, A, G one by one. Then land the key insight — model writes the graph.
D — Directed

Every edge has a direction. Node A feeds Node B. Not the other way around. The flow only goes forward.

A — Acyclic

No cycles. A node cannot point back to an earlier node. The Planner is explicitly prevented from emitting back-edges.

G — Graph

Nodes connected by edges. A node is one skill doing one job. An edge means "I need your output before I can start". Nodes with no unresolved edges run immediately — in parallel via asyncio.gather.

The key mental shift — say this clearly

In S7, the model was inside the loop, choosing the next tool each iteration. In S8, the model writes the graph. The Planner's JSON output is itself a program that the Executor runs. Same machinery dispatches the Planner, the Researcher, and the Critic. What varies is the prompt file and which tools are allowed.

Three properties of the graph

Acyclic by construction — Planner cannot emit a back-edge.  ·  Dynamic — new nodes added as old ones complete.  ·  Persisted — every write is atomic (write-tmp → os.replace). Kill the process, resume from the last successful node.

What changed
Six changes — S7 untouched
All S7 modules are byte-identical. ~1500 lines across 8 new files.
🎙One sentence per change. End with the byte-identical point — it's important.
1 · flow.py

The orchestrator. Graph wrapper over NetworkX DiGraph. Executor runs asyncio.gather on all ready nodes simultaneously.

2 · agent_config.yaml

Skill catalogue. A skill is a triple: prompt file + tools allowed + temperature. One Python class, parameterised by YAML. No per-skill subclasses.

3 · Planner

Always the first node. Reads the query, outputs JSON with rationale + node specs. That JSON is the graph the Executor runs.

4 · Critic

Auto-inserted on every outgoing edge from a distiller. Temperature 0.0 — deterministic pass/fail. On fail: child skipped, recovery Planner queued.

5 · persistence.py

Atomic JSON writes via os.replace. Resume reads graph.json, resets running → pending, continues. Resume at node boundary, not tool-call boundary.

6 · Gateway V8

Port 8108. Adds agent + session tags per call. /v1/cost/by_agent endpoint. agent_routing.yaml pins skills to providers. Retry-on-5xx built in.

Critical point

perception.py, decision.py, action.py, memory.py, mcp_server.py, artifacts.py, vector_index.py — all byte-identical to S7. Students with a working S7 implementation can understand S8 without touching any role from the previous session.

Say this about the speedup

The asyncio.gather barrier means the Coder cannot start until every input has landed. Cost of the parallel layer = max(56.6, 57.1, 41.7) = 57.1s. Sequential would have been 155s. Saving: 98 seconds on just this layer.

The key design insight

Optimising Nigeria (41.7s) saves nothing. Only optimising the slowest branch — Brazil at 57.1s — pays back directly. This is the question anyone building their own DAG should ask before adding branches: which branch is likely to dominate, and why?

Token bill

S7 re-sends cumulative history every iteration. S8 Researchers are scoped — each only sees USER_QUERY and its specific question. 17k tokens for a similar query vs 54k in S7. Factor of 3x reduction.

The key lesson — say this clearly

The splice mechanism is wired and tested — 4 unit tests in test_recovery.py cover every path. The verdict quality is a prompt problem, not an orchestrator problem. Wiring problems = fix the orchestrator. Policy problems = fix the Critic's prompt or give it a tool.

The rubber stamp finding (don't hide it)

The forcing query: write a haiku in 4-6-4 syllables. The Coder wrote 5-7-5. The Critic approved it three times saying "follows the 4-6-4 structure". The LLM cannot count syllables. The wiring worked. The verdict was wrong. Fix = give the Critic a count_syllables tool. This is what Rohan calls the mechanism-policy separation.

Task 4
Coder + sandbox — trust and verify
Tokyo · Delhi · Shanghai — which two differ by less than 5%? Session s8-4938eac9.
🎙Point at the diamond shape in the DAG diagram. Explain why computation beats text guessing.
Why coder here

A formatter alone might say "approximately similar". It cannot reliably compute 4.09%. The Coder is prompted to output JSON with two fields: code (Python snippet) and summary (natural language with the computed answer). The sandbox runs the code. The formatter reads the summary.

The diamond

Coder fans out to Formatter and SandboxExecutor simultaneously. Formatter trusts the LLM summary. Sandbox verifies by running the code. User sees formatter's answer. Sandbox result is logged to NodeState only.

Sandbox scope

Usability boundary, not security. ENV scrubbed to: PATH HOME LANG LC_ALL LC_CTYPE. Temp dir. 30s timeout. 1MB output cap. No network isolation. No filesystem restriction outside tmp. Fine for student code.

The architectural point

Once the architecture admits real execution alongside LLM reasoning, failure modes split. An LLM error is fixable by prompt or model. A subprocess error is fixable by reading stderr. The diamond is the simplest expression of that split.

Honest design choices — say these, don't hide them

1. Sandbox is usability only — no seccomp, no network isolation, no privilege drop. For student code only. Production needs rlimit + namespaces.

2. Mid-tool-call resume not supported — researcher killed mid-tool-call re-runs from the top. ~60 lines documented in DEFERRED.md.

3. Critic is a generic LLM judge — rubber stamp for syllable counts and exact arithmetic. Fix: give Critic targeted tools (count_words, count_chars, etc.).

4. No Skill abstraction above YAML — one if-skill-name == sandbox_executor special case. Tolerable for now. Second such case triggers proper abstraction.

5. agent_routing.yaml not hot-reloaded — changing a provider pin requires gateway restart (15 seconds).

Session 9 addresses the top 3

Browser-grounded research replaces fetch_url. Mid-tool-call resume via partial_messages in NodeState. Critic with tools for grounded verdicts. Semantic chunking also possible depending on scope.
